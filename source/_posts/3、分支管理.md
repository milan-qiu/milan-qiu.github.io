<h2>创建使用分支</h2>
<p>创建dev分支</p>
<div class="cnblogs_code">
<pre>git branch dev</pre>
</div>
<p>&nbsp;</p>
<p>一、创建并切换到新的分支（dev分支）</p>
<div class="cnblogs_code">
<pre>git <span style="color: #0000ff;">switch</span> -c dev</pre>
</div>
<p>&nbsp;</p>
<p>二、查看当前分支</p>
<div class="cnblogs_code">
<pre>git branch</pre>
</div>
<p>&nbsp;</p>
<p>三、修改完文件，并add、commit后，切换回master分支</p>
<div class="cnblogs_code">
<pre>git <span style="color: #0000ff;">switch</span> master</pre>
</div>
<p>&nbsp;</p>
<p>四、将dev合并到master</p>
<div class="cnblogs_code">
<pre>git merge dev</pre>
</div>
<p>&nbsp;</p>
<p>五、删除dev分支</p>
<div class="cnblogs_code">
<pre>git branch -d dev</pre>
</div>
<p>&nbsp;</p>
<p>六、查看分支合并情况</p>
<div class="cnblogs_code">
<pre><code class="php">git log --graph --pretty=oneline --abbrev-commit</code></pre>
</div>
<p>&nbsp;</p>
<h2>解决冲突</h2>
<p>一、若合并分支发生冲突（git merge dev）</p>
<p>&nbsp;</p>
<p>二、查看发生冲突的文件</p>
<div class="cnblogs_code">
<pre>git status</pre>
</div>
<p>&nbsp;</p>
<p>三、打开发生冲突的文件，手动更改再add、commit</p>
<p>&nbsp;</p>
<p>四、删除分支</p>
<div class="cnblogs_code">
<pre>git branch -d dev</pre>
</div>
<p>&nbsp;</p>
<h2>合并分支问题</h2>
<p>一、若合并分支时使用的时Fast forward方式，后删除分支后会产生分支信息丢失</p>
<p>&nbsp;</p>
<p>二、禁用Fast forward方式</p>
<div class="cnblogs_code">
<pre>git merge --no-ff -m <span style="color: #800000;">"</span><span style="color: #800000;">禁用fast forward合并</span><span style="color: #800000;">"</span> dev</pre>
</div>
<p>&nbsp;</p>
<h2>Bug分支</h2>
<p>一、在dev上开发遇到bug时，将当前工作区储藏起来</p>
<div class="cnblogs_code">
<pre>git stash</pre>
</div>
<p>现在用git status 查看是干净的</p>
<p>&nbsp;</p>
<p>二、若问题在master上，就在master上建立bug分支</p>
<p>三、切换bug分支解决问题后，切回master进行合并，并删除bug分支</p>
<p>&nbsp;</p>
<p>四、切换回dev分支，查看藏起来的工作</p>
<div class="cnblogs_code">
<pre>git stash list</pre>
</div>
<p>&nbsp;</p>
<p>五、两种恢复方法</p>
<p>1、一是用<strong><code>git stash apply</code>恢复</strong>，但是恢复后，<strong>stash内容并不删除</strong>，你需要用<strong><code>git stash drop</code>来删除</strong></p>
<p>2、用<strong><code>git stash pop</code>恢复</strong>，<strong>stash内容也会删</strong>了</p>
<p>&nbsp;</p>
<p>六、可对当前工作进行多次隐藏，隐藏后查看列表</p>
<div class="cnblogs_code">
<pre>git stash list</pre>
</div>
<p>&nbsp;</p>
<p>七、恢复其中一次</p>
<div class="cnblogs_code">
<pre>git stash apply stash@{<span style="color: #800080;">0</span>}</pre>
</div>
<p>&nbsp;</p>
<p>八、在master上的bug，dev也会存在，记住提交bug时的commit id</p>
<div class="cnblogs_code">
<pre>git cherry-pick 4c805e2</pre>
</div>
<p>这样dev上的bug也会解决</p>
<p>&nbsp;</p>
<h2>Feature分支</h2>
<p>一、每添加一个新功能就添加一个feature</p>
<p>&nbsp;</p>
<p>二、功能实现后添加到dev，并删除分支</p>
<p>&nbsp;</p>
<p>三、若开发Feature的过程中，这个功能突然说不需要了</p>
<div class="cnblogs_code">
<pre><span style="color: #008000;">//</span><span style="color: #008000;">切换回dev，强制删除Feature分支</span>
git branch -D feature</pre>
</div>
<p>&nbsp;</p>
<h2>多人协作</h2>
<p>一、当你从远程仓库克隆时，实际上Git自动把本地的<code>master</code>分支和远程的<code>master</code>分支对应起来了，并且，远程仓库的默认名称是<code>origin</code>。</p>
<p>&nbsp;</p>
<p>二、查看远程库信息</p>
<div class="cnblogs_code">
<pre><span style="color: #008000;">//</span><span style="color: #008000;">查看远程库名称</span>
<span style="color: #000000;">git  remote

</span><span style="color: #008000;">//</span><span style="color: #008000;">查看远程库详细信息</span>
git remote -v</pre>
</div>
<p>&nbsp;</p>
<p>三、将本地的master推送到远程的master</p>
<div class="cnblogs_code">
<pre>git push origin master</pre>
</div>
<p>&nbsp;</p>
<p>四、将本地的master推送到远程的dev</p>
<div class="cnblogs_code">
<pre>git push origin dev</pre>
</div>
<p>&nbsp;</p>
<p>默认clone下来的项目只有master分支，怎么关联远程的dev分支到本地？</p>
<div class="cnblogs_code">
<pre>git checkout -b dev origin/dev</pre>
</div>
<p>做完开发add、commit后，推送到远程的dev分支</p>
<div class="cnblogs_code">
<pre>git push origin dev</pre>
</div>
<p>若有人做了同样的更改，你git push oringin dev推送不上去？</p>
<div class="cnblogs_code">
<pre><span style="color: #008000;">//</span><span style="color: #008000;">需要将先用git pull把最新的提交从origin/dev抓下来，然后，在本地合并，解决冲突，再推送<br /><br />//指定本地<code>dev</code>分支与远程<code>origin/dev</code>分支的链接</span>
git branch --<span style="color: #0000ff;">set</span>-upstream-to=origin/<span style="color: #000000;">dev dev<br /><br />//pull文件下来，手动更改<br />git pull

</span><span style="color: #008000;">//</span><span style="color: #008000;">随后再push上去</span>
git push origin dev</pre>
</div>
<p>&nbsp;</p>
<h2>Rebase</h2>
<p>rebase的目的是使得我们在查看历史提交的变化时更容易，因为分叉的提交需要三方对比。</p>
<p>一、将<code class="sql">git log <span class="comment">--graph --pretty=oneline --abbrev-commit 变直线</span></code></p>
<div class="cnblogs_code">
<pre>git rebase</pre>
</div>
<p>二、查看</p>
<div class="cnblogs_code">
<pre>git log --graph --pretty=oneline --abbrev-commit</pre>
</div>
<p>&nbsp;</p>
